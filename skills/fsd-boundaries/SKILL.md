# Границы Feature-Sliced Design

Перед добавлением файла найди владельца поведения, его потребителей и пару примеров той же роли. Сверь их с AGENTS.md, картой проекта и настройками импортов. Определи место, имя экспорта и границу, которую пересечёт потребитель. Создавай только те сегменты, которые требуются изменению.

| Слой | Когда разместить здесь код |
| --- | --- |
| app | Инициализация приложения, провайдеры и сборка маршрутов |
| pages | Композиция конкретного экрана и логика, используемая только этим экраном |
| widgets | Самостоятельный крупный блок интерфейса, объединяющий нижние слои |
| features | Законченное действие пользователя, которое имеет смысл выделить из экрана |
| entities | Модель предметного понятия, правила и представления, общие для действий с ним |
| shared | Инфраструктура, UI-примитивы и утилиты, применимые без знания предметных понятий |

- Используй слои, существующие в проекте. При выборе между страницей и новым слайсом проверь, кто ещё использует поведение и по какой причине оно меняется. Переиспользование в двух местах само по себе не делает предметную логику частью shared.
- Между слайсами направляй зависимости сверху вниз. Если двум фичам нужны результаты друг друга, собери их в странице или виджете и передай данные либо события через публичные контракты. Если обеим нужна одна операция над сущностью, проверь, принадлежит ли она этой сущности. Документированные исключения проекта применяй только в их заявленной области.
- Снаружи импортируй слайс через публичный вход, обычно `index.ts` в корне слайса. Экспортируй только нужные символы. Например, виджет может импортировать `SearchForm` из `features/search`, а внутренний компонент этой фичи — обращаться к соседнему модулю напрямую. Импорт собственного публичного входа из реализации может замкнуть цикл.
- Для shared и app сверяйся с принятыми входами сегментов. Для библиотеки проверь также поле `exports` в package.json и корневые реэкспорты. Если страница была ленивой, сохрани динамический импорт через доступную потребителю точку входа.
- После перемещения найди импорты по прежнему пути, включая динамические и типовые. Проверь направление новых зависимостей, запусти настроенные архитектурные проверки и typecheck. Если менялся публичный вход пакета или маршрут с ленивой загрузкой, проверь сборку и соответствующий вход со стороны потребителя.
