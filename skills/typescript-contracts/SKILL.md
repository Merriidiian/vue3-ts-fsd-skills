# Контракты TypeScript

1. Проследи путь значения от источника до потребителей. Уточни, где контракт задан явно (схема, тип библиотеки, сигнатура функции), где данные приходят во время выполнения и какие поля действительно нужны вызывающему коду. Сверь решение с локальными AGENTS.md, tsconfig и правилами ESLint.
2. Используй тип владельца данных. Для подмножества полей подойдёт `Pick`, для элемента типизированного массива — `Items[number]`. Если представление меняет смысл данных (например, преобразует строку даты в дату), опиши результат преобразования отдельно. При наличии кодогенерации меняй схему или запрос и запускай штатный генератор.
3. На границе с JSON, хранилищем или параметрами URL проверь фактическое значение. Начни с `unknown`, сузь тип проверкой либо валидатором, который уже используется в проекте. Приведение через `as` и оператор `!` пропускают эту проверку. Различай отсутствующее поле, `null`, пустую строку и ноль, если контракт придаёт им разный смысл.
4. Опиши взаимоисключающие состояния объединением с дискриминатором. Например, результат сохранения может иметь тип `{ ok: true; id: string } | { ok: false; message: string }`. Тогда проверка `result.ok` подсказывает потребителю, какое поле доступно. Применяй такую модель там, где независимые необязательные поля допускают невозможную комбинацию.
5. Экспортируй публичные типы через принятую точку входа. Для типов используй `import type` и `export type` согласно конфигурации проекта. Перед переименованием найди вызовы и реэкспорты, включая потребителей в шаблонах.
6. Запусти штатную проверку типов для затронутого пакета и линтер изменённых файлов. Для изменения обработки внешних данных проверь валидное и некорректное значение на том же входе, которым пользуется приложение.
